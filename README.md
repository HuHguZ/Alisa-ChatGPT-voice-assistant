# Alisa-ChatGPT-voice-assistant

Голосовой мост между **Яндекс Станцией Лайт 2** и голосовым режимом **официальной веб-версии ChatGPT**. Микрофоны и динамик колонки передаются на Linux-ПК; ChatGPT работает в Chromium на отдельном виртуальном экране, без окна на рабочем столе.

Проверено на Лайт 2 **YNDX-00028 / Plum** и CachyOS. Это рабочий эксперимент для своей колонки с уже полученным root и SSH. Инструментов получения root и образов прошивки в репозитории нет. Совместимость с другими моделями не проверена.

## Возможности

- **«Алиса, открой чат»** — открыть голосовой режим и продолжить предыдущий разговор.
- **«Алиса, создай новый чат»** — начать новый разговор.
- **«Алиса, закрой чат»** — завершить ChatGPT и вернуть обычную Алису.
- Синяя индикация во время ответа ChatGPT и два нисходящих тона после возврата к Алисе.
- Обработка голосовых команд на самой колонке через штатное облачное распознавание Яндекса.
- Во время GPT обработчик отменяет штатный ответ после распознавания команды. Vosk и отдельная модель на ПК не требуются.
- Пауза штатной музыки перед открытием ChatGPT и защита от её позднего возобновления во время разговора.
- Усиление голоса ChatGPT до +6 дБ с ограничителем пиков.
- Выбор сырого микрофона или штатного обработанного канала `vqe_0`.
- Сохранение предыдущего разговора между перезапусками.
- Возврат к Алисе, если голосовой звонок сайта закончился, а Chromium остался открыт.
- Пользовательская служба systemd с автозапуском при входе в Linux и повторным подключением после ошибки.

Для открытия обработчик принимает только «открой чат». Варианты «включи чат» и «запусти чат» режим не переключают.

ПК нужен всё время работы моста. Браузер начинает голосовой разговор только по команде. Обращение **«Алиса» обязательно**; команду закрытия произносите в паузе между ответами: во время собственного звука обработчик отклоняет новые пробуждения Алисы, чтобы ответ ChatGPT не управлял колонкой. Уже начатое распознавание команды закрытия может завершиться.

## Требования

- Лайт 2 с root, SSH по ключу и доступом к штатным ALSA, `socat`, `aplay` и Quasar.
- Linux-ПК в сети колонки, PipeWire с интерфейсом PulseAudio либо совместимый PulseAudio.
- Chromium, Xvfb, xauth, OpenSSH, ALSA utilities.
- Системный Python 3.11 или новее; компоненты моста используют стандартную библиотеку.
- Интернет на колонке для распознавания команд через Яндекс, включая выход из GPT.
- Clang и LLD для сборки ARM32-библиотек.
- Вход пользователя на официальном сайте ChatGPT с доступным голосовым режимом.

## Установка на CachyOS / Arch Linux

Клонируйте репозиторий в `~/Alisa-ChatGPT-voice-assistant` и перейдите в него. Затем:

```bash
sudo pacman -S --needed python chromium pipewire-pulse alsa-utils openssh socat xorg-server-xvfb xorg-xauth clang lld
python3 scripts/build.py
```

Скрипт создаёт ARM32-библиотеки для колонки и хостовые библиотеки для тестов в `build/`. ARM-сборка не требует копирования библиотек прошивки или установки компилятора на колонку.

Добавьте SSH-алиас `alice` по [примеру](examples/ssh-config). Укажите свои адрес, порт и ключ; заранее проверьте и сохраните ключ хоста колонки. Подключение должно работать без интерактивного пароля:

```bash
ssh -o BatchMode=yes alice 'uname -m'
```

Порт `2222` в примере относится к исходной конфигурации проекта; используйте фактический SSH-порт своей колонки. Не открывайте root-SSH или ADB колонки в интернет.

## Первый запуск и вход в ChatGPT

Запустите мост в терминале:

```bash
python3 bridge.py start
```

После сообщения `Bridge running` появятся устройства:

| Назначение | Имя |
| --- | --- |
| Микрофон колонки | `alice_station_mic` |
| Динамик колонки | `alice_station_speaker` |

Для первого входа, **до команды открытия чата**, в другом терминале откройте отдельный профиль браузера:

```bash
PULSE_SOURCE=alice_station_mic PULSE_SINK=alice_station_speaker \
  chromium --user-data-dir="$HOME/.local/state/alice-voice-bridge/browser-profile" https://chatgpt.com
```

Войдите самостоятельно на официальном сайте и закройте это окно. Теперь произнесите **«Алиса, открой чат»**. Последующие открытия используют тот же профиль в фоновом Chromium. Если сайт попросит повторный вход, закройте чат и снова выполните ручной вход этим способом.

Программа не извлекает cookies и токены авторизации. Профиль браузера содержит вашу сессию и хранится только локально. Не добавляйте его в репозиторий и не передавайте другим людям.

Управление из терминала:

```bash
python3 voice.py open
python3 voice.py new
python3 voice.py close
python3 voice.py status
python3 bridge.py status
```

## Обработанный микрофон

По умолчанию мост смешивает два сырых микрофона (48 кГц). Для проверенной
прошивки Plum можно передавать **`vqe_0` после штатной VQE-обработки**, тот же
канал, который выбран для входа Алисы:

```bash
ALICE_MICROPHONE_SOURCE=vqe python3 bridge.py start
```

Предварительно остановите уже запущенный мост. Для службы добавьте через
`systemctl --user edit alice-voice-bridge.service`:

```ini
[Service]
Environment=ALICE_MICROPHONE_SOURCE=vqe
```

Затем перезапустите службу. `microphone_source: vqe` и `microphone_rate: 16000`
в состоянии подтверждают выбранный режим. Для возврата к сырому входу задайте
`ALICE_MICROPHONE_SOURCE=raw` и снова перезапустите мост.

На колонке модуль `station/vqe_tap.c` копирует выход `YandexVqeC_GetOutputChannelData`
для типа 6, канала 0. Исходные буферы и результат вызова сохраняются. Обработанный
моносигнал передаётся в PCM S16_LE 16 кГц: 32 КБ/с вместо 96 КБ/с у сырого потока.
PipeWire преобразует частоту для виртуального устройства браузера. Количественное
улучшение распознавания и эхоподавления ещё не измерено.

Проверена библиотека `libyandex_evil.so` с SHA-256
`fa7ad1544fe9ddfccedcf15acc031768345b0b8c7333bc1c0b47bc476dd4152f`.
Это недокументированный ABI, поэтому другая сборка в режиме VQE отклоняется
до смены профиля запуска. Сначала требуется проверить её совместимость;
сырой режим не зависит от этого ABI. Образы и библиотеки прошивки не включены.

## Автозапуск

Сначала остановите мост в терминале через Ctrl+C. Если проект расположен в другом каталоге, исправьте пути в [примере службы](examples/alice-voice-bridge.service).

```bash
mkdir -p ~/.config/systemd/user
cp examples/alice-voice-bridge.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now alice-voice-bridge.service
```

Служба запускается при входе пользователя в Linux. Если колонка недоступна или подключение оборвалось, после завершения неудачной попытки повтор начинается через 20 секунд. Это не периодический перезапуск исправного соединения. После перезагрузки колонки служба заново подключается и подготавливает аудиомост; сам голосовой разговор не запускается.

```bash
systemctl --user status alice-voice-bridge.service
journalctl --user -u alice-voice-bridge.service -f
systemctl --user stop alice-voice-bridge.service
systemctl --user disable --now alice-voice-bridge.service
```

На самой колонке постоянный автозапуск ChatGPT не устанавливается. После обычной перезагрузки она сначала использует штатный запуск, затем работающая служба на ПК подключает временный профиль моста.

## Устройство проекта

`station/capture_tap.c` через `LD_PRELOAD` копирует штатный микрофонный захват после `snd_pcm_readi`, смешивает два микрофона и исключает канал обратной связи динамика. Неблокирующий Unix datagram не задерживает штатный процесс при отсутствии или переполнении приёмника. В обычной работе вход Алисы остаётся активным и в режиме ChatGPT: подавлением её диалога управляет отдельный обработчик.

При `ALICE_MICROPHONE_SOURCE=vqe` вместо сырого модуля загружается `station/vqe_tap.c`: копирование выполняется после штатной обработки, по 10 мс или меньше на датаграмму. Медленный или отсутствующий приёмник также не блокирует Алису. Проверки на синтетическом VQE проверяют выбор канала, масштабирование, насыщение PCM, сохранение оригинальных данных, ошибок и `errno`.

`bridge.py` передаёт PCM через SSH и создаёт виртуальные аудиоустройства. Обратный путь использует `station/playback_worker.c`: блоки по 20 мс, буфер ALSA 80 мс, очередь на ПК до 120 мс и максимум восемь неподтверждённых блоков. Окно 160 мс помогает заполнять ALSA-буфер при колебаниях задержки Wi-Fi; в состоянии оно видно как `playback_window_ms`. При запуске и после восстановления ALSA воспроизведение начинается после заполнения до 60 мс; порог ограничен фактическим размером буфера. Это даёт запас перед следующим блоком, не увеличивая буфер 80 мс. Дополнительные блоки в пути могут добавить до 80 мс задержки по сравнению с прежним окном из четырёх блоков, но ограничивают пропуски при колебаниях RTT; паузы сети на сотни миллисекунд всё ещё могут быть слышны. В журнал выводятся фактические размеры буфера и код ошибки при восстановлении (`ALICE_PLAYBACK_CONFIG`, `ALICE_PLAYBACK_RECOVER`); `playback_underruns` считает восстановления, а не число слышимых запинок. Просроченный звук отбрасывается. `audio_gain.py` усиливает звук без дополнительной очереди и ограничивает пики на 95% полной шкалы.

`microphone_transport.py` непрерывно принимает входящий звук в очередь максимум 60 мс. При переполнении остаются свежие блоки; блоки старше 120 мс не отправляются в PipeWire. Канал stdin процесса `pacat` ограничен 4 КиБ, а буфер записи asyncio — 20 мс PCM. Без этих ограничений несколько очередей могли накапливать секунды старой речи. В состоянии видны `microphone_queue_ms`, `microphone_dropped_bytes` и `microphone_pipe_bytes`. При сбоях сети часть входа может пропасть, но старая речь не должна накапливаться в очереди моста.

Для входа 16 кГц те же 4 КиБ Linux pipe соответствуют максимум 128 мс PCM
(для 48 кГц — около 43 мс). Это предел ёмкости, а не обязательное заполнение
или постоянная задержка. Очередь Python остаётся ограничена 60 мс в обоих режимах.

`station/native_agent.c` работает на колонке отдельным процессом и подключается к локальному IPC `aliced` на `127.0.0.1:9875`. В обычном режиме он перехватывает только точные финальные команды чата; остальные запросы Алисы проходят без отмены. В режиме GPT сохраняется штатный сеанс распознавания, включая звук сразу после слова «Алиса». После завершения голосового ввода, при финальном результате в состоянии `BUSY`, обработчик отменяет штатный ответ локально и передаёт на ПК только метки команд `open`, `new`, `close`. Посторонние запросы в этом режиме тоже отменяются. Повторы одного запроса исключаются. Если всё же начинается озвучивание Алисы, дополнительно отправляется `STOP_TTS`. Формат IPC сверялся с [quasar-protos](https://github.com/v3rt3p/quasar-protos) и [spotiya](https://github.com/klockky/spotiya/blob/main/src/voice.rs).

Для подтверждённых голосовых команд открытия/создания чата агент отправляет `CANCEL_DIALOG_AND_CLEAR_QUEUE` (метод 6) с `request_id` этой команды. Метод очищает очередь и отменяет диалог. Отправка разрешена после окончания речевого ввода, в `BUSY`, один раз на запрос. Закрытие, подавление остальных запросов в GPT и аварийный возврат используют прежний `STOP_CONVERSATION` (3), остановка озвучки — `STOP_TTS` (14). Счётчик отправленных очисток доступен в `voice.json → native_agent.queue_clear_requests`; текст речи и идентификаторы в него не записываются.

`voice.py` управляет браузером и передаёт обработчику режим и сигнал доступности раз в секунду. Если уже запущенный звонок перестаёт захватывать микрофон на три секунды, контроллер закрывает оставшийся Chromium, возвращает Алису и подаёт сигнал. В состоянии причина отмечается как `web-call-ended`. Запуск нового звонка исключён из этой проверки. При закрытии управляющего канала или отсутствии сигнала восемь секунд обработчик на колонке отменяет активный штатный запрос и возвращает обычную Алису. Распознавание фраз остаётся облачным, через Яндекс; перенос обработчика на колонку не делает его автономным от интернета.

`browser_control.py` управляет отдельным Chromium через закрытый DevTools pipe. Отладочный TCP-порт не открывается. Xvfb работает без TCP с временным Xauthority. При закрытии сначала завершается голосовой сеанс сайта, затем сохраняется адрес разговора и закрывается браузер.

При открытии чата контроллер направляет запись и воспроизведение выделенного браузера на устройства колонки и снимает сохранённое PulseAudio заглушение его потоков. Сам факт захвата не означает, что поток передаёт звук: заглушение может сохраняться после перезапуска Chromium. Другие профили браузера и общее отключение виртуального микрофона не изменяются; при отключённом микрофоне открытие завершается ошибкой и возвращает Алису.

В режиме `ALICE_AUDIO_FOCUS_MODE=native` мост получает штатный канал DIALOG через `AudioFilePlayerCapability`. Перед открытием браузера агент ждёт относящееся к своему request_id событие `FOCUS_CHANGED` с `has_audio_focus=true`. На входе отправляется одна пауза музыки; если Алиса ещё завершает голосовой ввод, пауза откладывается до IDLE. Периодический запрос паузы каждые 500 мс в этом режиме отключён. После выхода музыка остаётся на паузе до обычной команды продолжения. Штатный фокус может приглушать другой контент и сам по себе не означает остановку любого звука. Вывод GPT через ALSA остаётся отдельным от штатного плеера.

### Владение штатным аудиофокусом

Агент создаёт одну локальную FilePlayer activity с каналом DIALOG и зацикленным файлом тишины. Штатный повтор файла сохраняет activity. PCM разговора идёт прежним ограниченным ALSA-транспортом; регистрация произвольного внешнего AudioClient здесь не заявляется. Временный hard link с уникальным именем принадлежит одному экземпляру агента, а шаблон WAV создаётся кодом `audio_focus.py`. Прошивка и её звуковые файлы для этого не изменяются.

Отдельный процесс на колонке следит за heartbeat агента через pipe. При EOF, завершении агента или отсутствии heartbeat 10 секунд он через новое локальное IPC-соединение останавливает только принадлежащий этому агенту файл и удаляет ссылку. Он удерживает lock до окончания очистки. При обычном выходе агент сначала снимает activity и завершает сторожа. Временная передача фокуса распознаванию Алисы сохраняет разговор GPT. Если прошивка завершила файловую activity, агент получает её заново после завершения штатного ввода и перехода в IDLE; само обращение «Алиса» разговор не закрывает. Ошибка первоначального получения фокуса или повторные неудачи восстановления возвращают режим Алисы; браузер не запускается без первоначального подтверждения фокуса. Это защита от отказа агента, а не гарантия при одновременной принудительной остановке сторожа и агента или недоступном Quasar.

Протокол проверен для maind SHA-256 `7d431541e2737a94f8499953204dbb1306877e0cf7d36170c4b1a9e19974ba14`; перед установкой профиль проверяет хеш. Для явного возврата к прежнему периодическому контролю паузы предусмотрен `ALICE_AUDIO_FOCUS_MODE=pause`. Автоматически подменять им неуспешное получение фокуса мост не будет.

Проверки: реальный тихий acquire/replay/release на Lite 2; host IPC-тесты сопоставления request_id, тайм-аута, EOF, SIGKILL и SIGSTOP агента; контроллер проверяется с настоящим C-агентом и тестовым браузером. Акустическое качество, поведение всех будильников и все конкурирующие capability этим не покрыты.

`indicator.py` удерживает управление кольцом весь режим GPT, включая открытие голосового звонка: штатные вспышки Алисы на обращение скрыты, но её распознавание продолжает работать. В паузах кольцо погашено, при ответе GPT три RGB-зоны плавно переливаются разными цветами с лёгкой пульсацией яркости. Радужный цикл — 6 секунд, обновление — 10 кадров в секунду; дополнительные очереди звука не создаются.

По умолчанию выбран `ALICE_LED_STYLE=rainbow`; `ALICE_LED_STYLE=blue` возвращает синий цвет во время ответа. Для службы стиль можно задать через `systemctl --user edit alice-voice-bridge.service`:

```ini
[Service]
Environment=ALICE_LED_STYLE=blue
```

После изменения перезапустите службу. В `indicator.json` видны `style`, `chat_active` и `speaking`.

`station/indicator.sh` сохраняет цвет и активный LED-триггер каждого канала и временно отключает штатные триггеры. При выходе из GPT, завершении соединения или истечении двухсекундной аренды возвращаются сохранённые триггеры анимации. Другой новый владелец триггера сохраняется. Аппаратное выключение микрофонов определяется независимо от LED по GPIO с меткой `mute-switch`: на проверенной Plum он active-low. Если микрофоны выключены или состояние недоступно, управление сразу возвращается штатной индикации, чтобы красное предупреждение не скрывалось. На другой плате этот GPIO-путь сначала нужно проверить. `mode_cue.py` подаёт сигнал после закрытия браузера и восстановления входа Алисы.

Системные `/etc/asound.conf` и `/system/vendor/quasar/launch.json` не редактируются. Временный профиль, библиотеки и управляющие файлы находятся в `/data/opt/alice-voice/`. При подготовке профиля действует трёхминутный автоматический откат, который снимается после успешной проверки микрофонного потока.

## Данные и восстановление

Состояние хранится в `~/.local/state/alice-voice-bridge/`: профиль браузера, Unix-сокет управления, журналы, счётчики и адрес последнего разговора. В `conversation.json` сохраняется только адрес `/c/<UUID>` без параметров и содержимого сообщений, с правами `0600`. Аудиозаписи с микрофонов на диск не сохраняются. Во время работы моста микрофонный поток непрерывно передаётся на ПК; при включённом голосовом режиме его использует сайт ChatGPT.

Остановка службы закрывает её браузер, удаляет виртуальные устройства и возвращает штатный профиль колонки. Это предотвращает переключение живого разговора на физический микрофон ПК после удаления виртуального устройства.

Аварийное восстановление после остановки моста:

```bash
ssh alice /data/opt/alice-voice/profile.sh stock
```

Если включён автозапуск, сначала остановите службу, чтобы она не повторяла запуск во время восстановления.

## Ограничения

- Команды переключения и управление мостом требуют работающего ПК и локальной связи с колонкой.
- Доступность ChatGPT определяется по запуску захвата микрофона браузером. После завершения захвата автоматически возвращается Алиса, но зависшее соединение при продолжающемся захвате так не определяется. Команда «Алиса, закрой чат» требует облачного распознавания Яндекса и произносится в паузе между ответами. Во время незавершённой попытки открытия повторные действия ожидают её завершения.
- Ошибка запуска возвращает обработчик в обычный режим Алисы. Если облако Яндекса недоступно, голосовой выход из GPT не гарантируется; с ПК остаётся команда `python3 voice.py close`. При полном отсутствии интернета обычные облачные ответы Алисы тоже недоступны.
- По умолчанию используются сырые микрофоны; обработанный VQE-вход включается отдельно для проверенной прошивки. Качество подавления эха, перебивание и физическая кнопка выключения микрофонов не прошли отдельную полную проверку.
- Изменения сайта могут потребовать обновить выбор кнопок браузера. Обходы проверки входа не реализованы.
- Настройки очередей рассчитаны на домашнюю сеть. Перенос на VPS требует туннеля и адаптации звукового транспорта.

## Проверки

```bash
python3 scripts/build.py --target host
python3 -m unittest discover -s tests -v
```

Автоматические проверки используют синтетический PCM, ALSA `null` и подставные метаданные PulseAudio: протокол подтверждений, сохранение обратной связи, отсутствие блокировок захвата, точные команды, разбор финальных событий Алисы, повторные пробуждения и закрытие после постороннего запроса, обработка потери канала, отдельная команда паузы плеера, защита от позднего запуска музыки и её освобождение после выхода, усиление без переполнения, сохранение адреса разговора и возврат подсветки. Интеграционная проверка запускает настоящий C-обработчик с Python-контроллером, выполняет два цикла открытия и закрытия, проверяет отсутствие двойной отмены и возврат к Алисе после завершения звонка при живом браузере. Проверки аудиопотоков воспроизводят сохранённое заглушение и неверную маршрутизацию, не затрагивая другой профиль браузера или общее отключение микрофона. Для микрофонной очереди проверяются сохранение свежего конца потока при перегрузке, отбрасывание просроченных блоков и фактическое ограничение Linux pipe дочернего процесса.

Дополнительные проверки VQE используют синтетический движок: проверяются выбор обработанного канала, преобразование float32 в PCM, сохранение буферов и ошибок штатного вызова, работа при отсутствующем или переполненном приёмнике. Для воспроизведения моделируется underrun на ALSA `null`: проверяются заполнение перед стартом, ограничение порога фактическим размером буфера и сохранение подтверждений блоков. Для микрофона 16 кГц проверяется тот же предел очереди 60 мс.

На исходной колонке также проверены разговор через сайт, синяя индикация, физическое воспроизведение двух тонов и автоматическое восстановление после настоящей перезагрузки. В одном замере мост восстановился за 56,9 с; это результат конкретной сети, а не гарантированный срок. Личные отчёты, PID, адреса устройств и резервные копии в репозиторий не включены.

Исходники дополнительных проверок с синтезированной речью находятся в `test-tools/`; их зависимости и модель Piper нужны только для таких проверок. Они запускают реальный голосовой режим и возвращают исходную привязку к разговору. Не запускайте их во время своего разговора. Для этих проверок использовалось отдельное окружение Python 3.13 с `test-tools/requirements.txt` и русская модель Irina из [Piper](https://github.com/OHF-Voice/piper1-gpl). Модель находится в `test-tools/piper/ru_RU-irina-medium.onnx` вместе с её JSON-конфигурацией; в репозиторий она не включена.

`test-tools/verify_marker_resume.py` временно собирает `native_input.c` и перезапускает мост с отдельной тестовой библиотекой. В этом режиме входы из комнаты изолированы: команды подаются синтезированным PCM в штатное распознавание, а вопрос GPT — в виртуальный микрофон. Проверяются голосовой ответ, отсутствие ответов Алисы в GPT, обычный ответ после выхода, закрытие и открытие того же чата. В конце восстанавливаются рабочая библиотека захвата и исходная привязка к разговору.

Вариант `--activate` запускает штатный голосовой ввод через IPC и не проверяет детектор слова «Алиса». Срабатывание на синтезированный голос нестабильно; прохождение отдельных команд не заменяет проверку голосом владельца колонки.

Дополнительная проверка `test-tools/verify_marker_resume.py --open-only --activate` проверяет один голосовой вход и ровно один запрос очистки очереди. В режиме `--activate` тест удерживает IPC-соединение и ждёт `LISTENING` перед подачей синтезированного PCM. Это проверка в контролируемом тестовом профиле сырых микрофонов; детектор слова «Алиса» она не проверяет.

`test-tools/verify_web_close.py` подаёт синтезированную фразу закрытия только в микрофон веб-звонка и проверяет возврат к Алисе после завершения звонка без нативной команды. Выполняются два цикла, затем возвращается исходная привязка к разговору. Тест не проверяет штатный детектор слова «Алиса».

`test-tools/measure_latency.py` подаёт короткий тон и измеряет путь ПК → динамик колонки → её микрофоны → ПК. PCM обрабатывается в памяти; на диск сохраняются только численные результаты. Замер не включает время ответа ChatGPT.

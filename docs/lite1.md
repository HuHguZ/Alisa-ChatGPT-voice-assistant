# Станция Лайт 1 (yandexmicro) — нативный режим

Проверено 28 октября 2026 на одной Станции Лайт 1 (`yandex,station-micro`, `Yandex Station Micro v1.2`) с прошивкой `0.369.1.46.4778262442.20261013.297`. Root и SSH получены заранее, как и для Лайт 2. Проверен только **нативный режим**; мост на Лайт 1 не запускался.

## Что проверено на колонке

- **VQE-ABI.** Обёртка `YandexVqeC_GetOutputChannelData` имеет ту же сигнатуру (дизассемблирование). Диагностический preload показал, что stock-движок запрашивает тип `6`, индекс `0` блоками по 512 кадров 16 кГц. Пока Алиса говорила, канал обратной связи (тип `4`) и сырой микрофон (тип `1`) поднимались, а тип `6/0` оставался на уровне шума: это `vqe_0` с эхоподавлением. Готовый `vqe_tap.so` подходит без изменений.
- **aliced:9875.** Поток состояний совпадает: IDLE/LISTENING/SPEAKING/BUSY и запрос в поле `15 {1: текст, 2: 1, 4: 1}`. Готовый `native_agent.so` перехватывает «Алиса, открой чат». Это проверено повтором записанного потока в контейнере и живой командой.
- **Речь Алисы** идёт через `tts_gate.so` и `alice_native_tts` → `default` (softvol → dmix → `hw:0,0`).
- **Клиент** `alisa-standalone` из пакета запускается без пересборки (`audio_pipeline_revision` 5, RSS около 10 МиБ при разговоре).
- **`native verify`:** `real_reply_verified: true`, ALSA underrun 0. Автозапуск записывает `/etc/init.d/S99zz-alisa-voice` с временным `remount,rw`.

## Изменения для Лайт 1

- `doctor.py`: таблица `BUILDS` с маркерами device tree и проверенными парами `maind`/VQE для каждой модели. `socat` обязателен только для моста.
- `mute_gpio.so`: без строки `|mute-switch` в `/sys/kernel/debug/gpio` клиент считает микрофон выключенным и отправляет тишину. `run.sh` подгружает preload, только когда такой строки нет. Preload перенаправляет на файл состояния лишь чтение этого листинга. Он слинкован с `libdl`: в glibc 2.30 `dlsym` находится там, а preload наследует и busybox `sh` индикатора.
- `indicator.sh` и демо подсветки: если нет `plum`, используется `micro`. При отсутствии аппаратного переключателя индикатор не уступает подсветку.

Кнопка отключения микрофона Лайт 1 программная. Её влияние на разговор GPT отдельно не проверялось.

## Вход с Windows (экспериментально)

Мастер и браузерный вход CLI рассчитаны на Linux. Для нативного режима проверен один путь с Windows 11 и Python 3.14:

1. Доступ к колонке по ключу и известный ключ хоста (`ssh -p 2222 root@<IP>` один раз).
2. `python -X utf8 alisa.py native install --yes --no-start --host <IP> --port 2222 --user root --identity <ключ>`.
3. Chromium (не Chrome; проверка ищет `chrome.exe` в стандартной папке Chromium) и `python -X utf8 engines\native\tools\windows_login.py`. Вход выполняется в обычном окне без DevTools. Затем короткий второй проход открывает только `about:blank` и читает cookie сессии и User-Agent через DevTools уровня браузера. Токен доступа колонка получает сама при проверке входа.
4. `python -X utf8 alisa.py native start`, затем `native verify` и `native autostart on`.

Замечания:

- Cloudflare отвечает `403 cf-mitigated: challenge` не-браузерным клиентам `chatgpt.com`, в том числе на `/api/auth/session` и `/realtime/wm`. Колонка проходит с `cf_clearance`, полученным в обычном окне с того же внешнего IP и User-Agent. Если страница была открыта с подключённым DevTools, Cloudflare останавливался на «Один момент…», и такой `cf_clearance` колонка не принимала (`session_refresh_challenge_403`). Как долго действует полученный пропуск, пока не известно. При этой ошибке вход нужно повторить.
- В процессе, запущенном из сеанса службы OpenSSH Server (не из консоли), Windows OpenSSH зависает, если его stdio — анонимные pipe. Из обычной консоли или задачи в интерактивном сеансе всё работает.
- Без `-X utf8` старые версии читали `config.json` в cp1251, и русские фразы команд портились. Теперь CLI читает JSON явно в UTF-8.

Мост на Windows по-прежнему не поддерживается.
